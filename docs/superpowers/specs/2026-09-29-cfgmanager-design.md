- **Date:** 2026-09-29
- **Author:** Antigravity (Autonomous Mode)
- **Status:** Proposed
- **Target Platform:** Raspberry Pi 5 (AArch64 / BCM2712)
- **Target Framework:** Legato Application Framework
- **Implementation Language:** C++17 (`-std=c++17`)
- **Verification Standard:** Google Test (GTest) with C2 Branch/Condition Coverage

---

## 1. Overview & Objectives

The `CfgManager` is a centralized configuration management service for the Legato Application Framework. It provides a secure, decoupled service layer exposing Legato IPC APIs for setting, retrieving, and subscribing to configuration changes.

### Key Objectives
1. **Three-Tier Data Classification:**
   - **`RawData`:** Non-sensitive data stored directly as plain text/values in Legato `configTree`.
   - **`SensitiveData`:** Sensitive parameters (passwords, tokens, API keys) encrypted via AES-256-GCM prior to storage in `configTree`.
   - **`SecureData`:** High-security credentials stored directly inside ARM TrustZone (Secure World) and excluded from standard non-secure filesystem trees.
2. **Strict Consumer Isolation (`cfgId` Abstraction):**
   - Consumers (client applications) identify configuration items exclusively using a composite 32-bit `cfgId` encoding the item's identity, domain, and data flags.
   - Consumers are completely shielded from internal storage paths (whether in `configTree` or TrustZone).
3. **Envelope Encryption & TrustZone Key Management:**
   - The master encryption key is generated and sealed within TrustZone.
   - The crypto engine utilizes hardware-accelerated AES-256-GCM (ARMv8 Crypto Extensions via OpenSSL 3.0) with unique 12-byte initialization vectors (IVs) and 16-byte authentication tags.
4. **Pub/Sub Event Mechanism:**
   - Real-time event notifications (`ChangeEvent`) dispatched to subscribed clients when configuration values are modified.
5. **Modern C++17 Implementation & GTest C2 Coverage:**
   - Production code written in modern C++17 (RAII, zero-cost abstractions, strong typing).
   - Comprehensive Google Test unit test suite achieving high-coverage C2 branch testing for all business logic and edge cases.

### Module Responsibilities

1. **`IpcServer` (`cfgManagerServer.cpp`):**
   - Implements Legato RPC handler stubs generated by `ifgen` from `cfgManager.api`.
   - Translates incoming C RPC arguments into C++17 objects (`std::string_view`, `std::span<const uint8_t>`).
   - Delegates operations to `CfgRouter` and `EventDispatcher`.

2. **`CfgRouter` (`core/cfgRouter.hpp`, `core/cfgRouter.cpp`):**
   - Decodes composite 32-bit `cfgId`:
     - Checks category flags (`RAW`, `SENSITIVE`, `SECURE`).
     - Extracts Subsystem and Item ID.
   - Maps `cfgId` to internal storage paths (e.g. `/cfgManager/subsys_01/item_0023`).
   - Rejects unmapped or malformed IDs before accessing storage.

3. **`CryptoEngine` (`crypto/cryptoEngine.hpp`, `crypto/cryptoEngine.cpp`):**
   - Implements AES-256-GCM authenticated encryption/decryption using OpenSSL 3.0 `EVP_CIPHER_CTX`.
   - Produces self-contained encrypted envelopes:
     - Header: 4-byte Magic (`"SENC"`), 12-byte Nonce/IV, 16-byte GCM Tag, 4-byte Ciphertext Length, followed by Ciphertext.
   - Encodes envelope as Base64 for string configuration entries; preserves raw byte buffer for binary entries.
   - Rejects corrupted or tampered data upon tag mismatch.

4. **`SecurityProvider` (`security/securityProvider.hpp`, `security/securityProvider.cpp`):**
   - Hardware abstraction interface (`ISecurityProvider`) for TrustZone storage.
   - **`OpteeBackend`:** Communicates with `/dev/tee0` using `libteec` and GlobalPlatform TEE Secure Storage commands.
   - **`SimulatedEnclaveBackend`:** Machine-bound encrypted fallback store located at `/var/config/cfgManager/secure_store` with file mode `0600`, keyed by hardware machine-id + platform salt.
   - Provides Master Key retrieval (`GetMasterKey`) for the `CryptoEngine`.

5. **`ConfigTreeBackend` (`storage/configTreeBackend.hpp`, `storage/configTreeBackend.cpp`):**
   - Interacts with Legato's `le_cfg` API.
   - Manages dedicated tree node `/cfgManager`.
   - Supports atomic string and binary read/write operations.

6. **`EventDispatcher` (`events/eventDispatcher.hpp`, `events/eventDispatcher.cpp`):**
   - Manages client subscriber callbacks.
   - Matches incoming change notifications by `cfgId` or subsystem mask.
   - Asynchronously triggers Legato IPC event handlers.

## 3. Data Modeling & Composite `cfgId`

### Bitfield Structure (32-bit Unsigned Integer)

```text
 31             24 23             16 15                              0 (Bit Position)
+-----------------+-----------------+---------------------------------+
|  Category/Flags |    Subsystem    |             Item ID             |
+-----------------+-----------------+---------------------------------+
```

- **Bits [0..15] (Item ID):** 16-bit unique item index (0x0000 - 0xFFFF).
- **Bits [16..23] (Subsystem):** 8-bit domain identifier:
  - `0x01`: System / Core
  - `0x02`: Network / Connectivity
  - `0x03`: Security / Authentication
  - `0x04`: Application / Custom
- **Bits [24..31] (Flags):**
  - Bit 24 (`0x01`): `CFG_FLAG_RAW` (Plain text storage in `configTree`)
  - Bit 25 (`0x02`): `CFG_FLAG_SENSITIVE` (Encrypted storage in `configTree`)
  - Bit 26 (`0x04`): `CFG_FLAG_SECURE` (TrustZone Secure Storage)
  - Bit 28 (`0x10`): `CFG_FLAG_READ_ONLY` (Cannot be modified after initial write)
  - Bit 29 (`0x20`): `CFG_FLAG_VOLATILE` (Memory-only, non-persistent)

### C++ Helper Macros & Inlines (`cfgId.hpp`)

```cpp
namespace cfg {

enum class Category : uint8_t {
    Raw       = 0x01,
    Sensitive = 0x02,
    Secure    = 0x04
};

enum class Subsystem : uint8_t {
    System   = 0x01,
    Network  = 0x02,
    Security = 0x03,
    App      = 0x04
};

constexpr uint32_t MakeId(Category cat, Subsystem sub, uint16_t item, uint8_t extraFlags = 0) {
    return (static_cast<uint32_t>(static_cast<uint8_t>(cat) | extraFlags) << 24) |
           (static_cast<uint32_t>(static_cast<uint8_t>(sub)) << 16) |
           (static_cast<uint32_t>(item));
}

constexpr Category GetCategory(uint32_t cfgId) {
    return static_cast<Category>((cfgId >> 24) & 0x07);
}

constexpr Subsystem GetSubsystem(uint32_t cfgId) {
    return static_cast<Subsystem>((cfgId >> 16) & 0xFF);
}

constexpr uint16_t GetItemId(uint32_t cfgId) {
    return static_cast<uint16_t>(cfgId & 0xFFFF);
}

} // namespace cfg
```

## 5. Security & Cryptographic Details

### Authenticated Encryption Structure (AES-256-GCM)
For `SensitiveData`:
1. **Key Derivation:** Master key (256-bit) provided by `SecurityProvider`.
2. **IV/Nonce:** 12 bytes generated securely using OpenSSL `RAND_bytes`.
3. **Payload Packing:**
   ```text
   +------------------+-------------------+--------------------+--------------------+--------------------+
   | Magic ("SENC")   | IV / Nonce        | GCM Auth Tag       | Ciphertext Length  | Ciphertext Payload |
   | 4 Bytes          | 12 Bytes          | 16 Bytes           | 4 Bytes (BE)       | N Bytes            |
   +------------------+-------------------+--------------------+--------------------+--------------------+
   ```
4. **Integrity Validation:** Upon retrieval, `EVP_DecryptFinal_ex` checks the 16-byte authentication tag against the ciphertext. If any bit was modified in `configTree`, decryption immediately fails with `LE_FAULT` and zeroizes the output buffer.

### TrustZone Backend Architecture
- **OP-TEE Detection:**
  At startup, `SecurityProvider` tests whether `/dev/tee0` exists and can be opened.
  - If open succeeds: initializes `TEEC_InitializeContext` and connects to the Secure Storage TA (UUID: `873eed8b-4f4d-452e-9d22-8d77d7da5bb9`).
  - If open fails (standard Raspberry Pi OS without OP-TEE firmware): initializes `SimulatedEnclaveBackend`.
- **Simulated Enclave Security:**
  - Storage path: `/var/config/cfgManager/secure_world/`
  - Protection: Sealed with a 256-bit machine-bound key derived via PBKDF2 (100,000 iterations of SHA-256) using `/etc/machine-id` and a dedicated salt.
  - POSIX file permissions: Directory `0700`, files `0600` owned by `root`.

## 6. Unit Testing Strategy & Google Test C2 Coverage

All core C++ components are designed to be testable independently of the Legato daemon runtime via clean dependency injection and mock interfaces:

1. **`CfgRouterTest`:**
   - Validates all category flag extractions (`RAW`, `SENSITIVE`, `SECURE`).
   - Validates invalid flags rejection (e.g. both RAW and SECURE set).
   - Validates subsystem and item ID boundaries (0, 0xFFFF, unknown subsystems).
   - Validates path generation and path collision prevention.
2. **`CryptoEngineTest`:**
   - Roundtrip string and binary encryption/decryption.
   - Tamper verification: bit flipped in IV, bit flipped in Tag, bit flipped in Ciphertext -> must fail decryption.
   - Empty buffer and maximum size buffer (4096 bytes) tests.
   - Null pointer and invalid parameter resilience.
3. **`SecurityProviderTest`:**
   - Master key generation, persistence, and consistency across instances.
   - Secure data write, read, overwrite, and delete.
   - Key non-existence handling.
4. **`EventDispatcherTest`:**
   - Register subscriber for specific `cfgId`.
   - Dispatch notification -> verify subscriber receives exact `cfgId` and payload.
   - Multiple subscribers for different `cfgId`s -> ensure no cross-talk.
   - Unsubscribe -> verify no further events delivered.

### C2 Coverage Requirement
- Every decision branch (`if/else`, `switch/case`, ternary operators) must have tests executing both the `true` and `false` paths.
- All tests will run under Google Test (`gtest_main`) built with `-std=c++17` inside the containerized build environment.

## 7. Sample Client Application (`samples/cfgClient`)

To verify end-to-end integration across Legato IPC:
- `cfgClient.adef` + `clientComponent`:
  1. Subscribes to `CFG_ID_WIFI_PASS` (Sensitive).
  2. Sets a RAW configuration (`CFG_ID_DEVICE_NAME = "rpi5-gateway"`).
  3. Sets a SENSITIVE configuration (`CFG_ID_WIFI_PASS = "SuperSecretP@ss!"`).
  4. Sets a SECURE configuration (`CFG_ID_PROV_TOKEN = "trustzone-token-9988"`).
  5. Verifies `GetString` returns exact plaintext for all three categories.
  6. Verifies subscriber callback was triggered with the updated password.
  7. Directly inspects `configTree` via `le_cfg` to demonstrate that `CFG_ID_WIFI_PASS` is stored as an encrypted `"SENC..."` string and cannot be read as plain text from the config tree.
